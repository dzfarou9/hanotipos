## 1. Customers and debts never synced from Firebase (`27554ba`)

**Root cause:** `_syncFromFirebase()` pushed customers and debt transactions
but never pulled them, so cloud data was missing locally after login.

- Added pull steps 9 and 10 in `sync_service.dart` — customers use
  last-write-wins on `updated_at`, debt transactions are add-only, both
  guard against re-adding rows pending a delete.
- `addCustomerWithId` / `addDebtTransactionWithId` now accept
  `createdAt` / `updatedAt` so pulled rows keep their original dates
  (critical for FIFO debt ledger ordering).
- Both fetches feed `allPullsSucceeded`, so a failure no longer advances
  the sync watermark.

## 4. Purchase screen product entry (`8379137`, `a462925`)

- Scanning an unknown barcode opens a quick-add dialog instead of only
  showing an error; the picker's empty state gained an add button.
- New products are **not** written to inventory on dialog confirm. They
  enter the cart as *pending* (badged "New") and are created only when the
  purchase saves, via `SyncService.addProduct` — Hive first with
  `isSynced: false`, then a Firebase push that flips the flag on success.
- The quick-add dialog deliberately omits quantity and low-stock fields:
  quantity comes from the purchase line.
- Existing products prefill their cost from `product.costPrice` and remain
  editable; edits write back to inventory on save.
- Cart feedback shows the product name for both scan and pick paths.

## 6. Reports net profit (`a462925`)

- `netProfit` = period revenue − cost of goods sold. COGS prices each sold
  unit from the product's current `costPrice`, mirroring the revenue sign
  convention: standalone returns subtract, units returned against a sale
  drop out, products without a cost contribute zero.
- New `ReportData.costOfGoodsSold` surfaces in the profit-card badge.
- Both "Coming soon" placeholders removed.

**Known limitation:** `SaleItem` does not snapshot the cost at time of
sale, so historical profit shifts if a product's cost later changes. The
agreed upgrade path is adding `SaleItem.costPrice` (needs `build_runner`
plus a Firestore field); historical sales would still lack cost data.

## 8. Subscription showed "trial" and "0 days" (`0c4ece1`)

**Root cause:** Hive stored only `subscription_end_date` and
`subscription_active`, so every fallback path had to invent the rest —
and `_hiveSubscriptionMap()` hardcoded `'plan_type': 'trial'`.

Confirmed by two observations: a paid account logged in and worked
normally but displayed as trial, while an account with no subscription
correctly hit the expired screen. Splash grants entry via the 48-hour
lease *without* requiring a successful query (3-second timeout), so the
UI was reading the Hive fallback, not Firestore.

Three defects, all fixed:

1. `_hiveSubscriptionMap()` hardcoded trial and omitted `start_date`,
   `auto_renew`, `payment_method`.
2. `Duration.inDays` truncates — 23 hours remaining displayed as `0`.
3. `loadAndSaveSubscriptionInfo` returned only 4 keys while
   `profile_screen` renders 7, so **start date and auto-renew were hidden
   even when the query succeeded**.

Changes:

- **New** `lib/helpers/subscription_helper.dart` — pure and tested:
  `daysRemaining` (ceiling, so a partial day counts as one),
  `isSubscriptionValid`, `isLeaseValid`. 14 tests.
- `database_service` persists the full snapshot (plan type, start date,
  auto-renew, payment method) and clears it on logout.
- `firebase_service` gained `_persistAndBuildSubscription()` as the single
  write-and-build point for all three server reads, plus
  `cachedSubscriptionInfo()` for instant offline display. `_hiveLeaseValid`
  delegates to the tested helper.
- Both trial-creation fallback branches now write `lastVerified`; the catch
  branch previously left the lease permanently invalid, denying offline
  access to that user forever.
- `profile_screen` renders cached data first, then the server result;
  plan-type helpers accept `null` and show a generic "Active subscription"
  label instead of claiming trial. `settings_screen` prefills from the
  shared cache rather than its own truncating arithmetic.

**Still unverified:** if the Firestore subscription query is itself failing
(rules or a missing composite index), the profile will now show "Active
subscription" with correct dates rather than the real plan name. The debug
log distinguishes the cases — check which of these appears on Profile:

- `⚠️ Firebase not available, using Hive subscription`
- `❌ Error getting subscription info` (with the error)
- `⚠️ No subscription found in Firestore`
- `✅ Subscription found: <plan> until <date> (<n> days remaining)`
