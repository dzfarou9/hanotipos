SECTION 1 — CRITICAL BUGS (fix first; data loss / money risk)
================================================================================

C1. STALE HIVE ADAPTER DESTROYS PURCHASE DATA ON EVERY RESTART
    File:    lib/models/purchase_model.g.dart:68-108
    Problem: The model declares @HiveField(11..15) — invoiceNumber,
             returnedItems, returnTotal, isFullyReturned, updatedAt —
             but the generated adapter only writes/reads fields 0-10.
             It was never regenerated after the fields were added.
    Impact:  - Supplier invoice numbers + ALL purchase-return state vanish
               on app restart.
             - availableForReturn() then allows re-returning already-returned
               quantities (real money loss).
             - updatedAt resets to DateTime.now() on reload, poisoning the
               LWW sync comparison (sync_service.dart:920) -> server purchase
               updates silently ignored forever.
    Fix:     dart run build_runner build
             (all other .g.dart files verified current)
    Effort:  ONE COMMAND. Highest value fix in the whole report.

C2. SYNC WATERMARK ADVANCES EVEN WHEN A PULL FAILS -> PERMANENT SILENT
    DATA LOSS
    File:    lib/services/sync_service.dart:715-717, 946-949
    Problem: Each fetch section swallows its error (catch { logError }),
             then saveLastSyncTime(now - 5min) runs UNCONDITIONALLY at the
             end. Any document that failed to fetch in that window is now
             older than the watermark and will NEVER be pulled again until
             a full-sync login.
    Aggravator: getSuppliers/getPurchases (firebase_service.dart:1585-1595,
             1652-1662) have NO fallback-to-full-pull and NO limit, so a
             missing composite index throws, is swallowed, and the watermark
             still advances.
    Fix:     Track per-section fetch success; only advance the watermark
             for sections that fetched cleanly (or skip advancing entirely
             on any error).
    Effort:  Medium (~30-50 lines in sync_service.dart).

C3. FAILED SERVER-DELETE + PULL = GHOST RESURRECTION
    File:    lib/services/sync_service.dart:341-415 + 724-741
    Problem: _syncPendingDeletes only calls Firebase delete + removes the
             tombstone on success. If the server delete FAILS (permissions,
             transient), the tombstone stays — but the same run's pull sees
             the still-existing server doc and RE-ADDS it to Hive.
    Impact:  Deleted products/sales/suppliers/purchases reappear in the UI
             permanently, and get pushed back to the server on any local edit.
    Fix:     Skip pull-re-add for any id present in the pending-deletes set;
             (or delete the local copy when the tombstone is created).
    Effort:  Small-medium (~20 lines).

SECTION 2 — HIGH BUGS (wrong behavior users will notice)
================================================================================

H1. CROSS-DEVICE SALE RETURNS NEVER PROPAGATE
    File:    lib/services/sync_service.dart:808
    Problem: Pull skips existing sales ("لا نعدل المبيعات الموجودة").
             Device A processes a return -> Firestore sale doc updated.
             Device B has the sale locally -> pull fetches it but skips it.
    Impact:  Device B's sale history shows the return as never made; stock
             diverges between devices. Movements have the same skip (828-851).
    Fix:     Apply LWW update for existing sales when server is newer AND
             local isSynced==true (same pattern already used for products
             at line 742-758).
    Effort:  Medium.

H2. DASHBOARD "YESTERDAY REVENUE" DOUBLE-COUNTS TODAY
    File:    lib/screens/dashboard_screen.dart:316-317
    Problem: isYesterday = createdAt.isAfter(startOfYesterday) &&
             createdAt.isBefore(endOfDay)   <-- endOfDay is TOMORROW midnight
    Impact:  Every sale today counts as BOTH today's and yesterday's revenue.
             The "vs yesterday" percentage on the welcome card is always wrong.
    Fix:     Change upper bound to startOfDay. ONE WORD.
    Effort:  Trivial.

H3. ADDPRODUCTWITHID MISSES CATEGORIES-CACHE INVALIDATION
    File:    lib/services/database_service.dart:413-443
    Problem: addProduct/updateProduct/deleteProduct all call
             invalidateCategoriesCache(); addProductWithId does NOT —
             yet that is exactly the method the sync PULL path uses
             (sync_service.dart:729).
    Impact:  New category arriving from Firebase stays invisible in
             dropdowns/filters up to 1 hour (TTL).
    Fix:     Add invalidateCategoriesCache() call. ONE LINE.
    Effort:  Trivial.

H4. UPDATESALEWITHRETURN IGNORES ITS isFullyReturned PARAMETER
    File:    lib/services/database_service.dart:778 vs 819
    Problem: Signature accepts bool isFullyReturned = false but the body
             recomputes it from quantities and never reads the parameter.
    Impact:  Misleading API; callers (SyncService:1011-1023) pass values
             that are silently discarded.
    Fix:     Remove the parameter, or honor it. Decide intended semantics.
    Effort:  Trivial.

H5. TOMBSTONES + SYNC STATE SURVIVE ACCOUNT SWITCH
    File:    lib/services/database_service.dart:282-305, sync_service.dart:84-90
    Problem: clearUserData deletes specific metadata keys but never removes
             pending_delete_* keys nor the sync-log box; SyncService has no
             reset for _isInitialSyncDone / _lastFirebasePullAt.
    Impact:  After logout -> login with a different account on the same
             device, the old account's tombstones replay forever (permission
             denied each sync, errors accumulate).
    Fix:     Clear pending-delete keys + sync log + reset SyncService flags
             in clearUserData / on login.
    Effort:  Small.

H6. UNGUARDED currentUser! IN FIRESTORE SUPPLIER/PURCHASE METHODS
    File:    lib/services/firebase_service.dart:1525, 1565, 1586, 1601, 1614,
             1653 (7 sites)
    Problem: Unlike every other method, these have no _isFirebaseAvailable
             guard and no null check: final uid = currentUser!.uid;
    Impact:  If the Firebase session expires mid-sync, throws "Null check
             operator used on a null value" -> aborts the WHOLE sync run.
             Also these skip the NetworkService retry wrappers used elsewhere.
    Fix:     Add the same guard pattern used by the other methods.
    Effort:  Small.

H7. WEB FIREBASE CONFIG USES THE ANDROID APP ID
    File:    lib/firebase_options.dart:63
    Problem: web appId = '1:542408928460:android:...' (must be ':web:').
    Impact:  Firebase.initializeApp fails or mis-registers on web
             (auth/analytics break). Android path is fine.
    Fix:     Create a web app in Firebase Console, run flutterfire configure
             or paste the correct appId.
    Effort:  Trivial (config only) — but requires Firebase Console access.
    Note:    Only matters if you ship the web build.

H8. SCANNER PERMANENTLY DEAD IF MOUNTED paused:true (LATENT)
    File:    lib/widgets/barcode_scanner_view.dart:103-121, 271
    Problem: initState skips _startCamera() when paused; the unpause path
             only calls _startImageStream(), which bails when the controller
             is null -> camera never starts for the widget's lifetime.
    Impact:  Currently UNREACHABLE (all 4 call sites mount unpaused), but
             it's a trap for the next feature that toggles pause.
    Fix:     Unpause branch: _cameraController == null ? _startCamera()
             : _startImageStream();
    Effort:  Trivial.

H9. AUTO-DISMISSIBLE WRAPPER CAN PERMANENTLY HIDE SYNC INDICATORS
    File:    lib/widgets/sync_progress_widget.dart:716-736
    Problem: _AutoDismissibleWidget has no key; its one-shot _isVisible=false
             survives a branch swap at the same tree position -> the next
             indicator renders as SizedBox.shrink() forever.
    Fix:     key: ValueKey(_status). Also remove dead
             SingleTickerProviderStateMixin (no ticker exists).
    Effort:  Trivial.
